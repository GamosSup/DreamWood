# AGENTS.md — всё, что нужно знать, чтобы работать над «Дримвуд»

Этот файл читай первым. Он написан для ИИ-агента (Kimi, Claude и других), который помогает развивать проект вместе с владельцем. Если что-то здесь расходится с кодом, верь коду и поправь этот файл.

## 1. Что это
«Дримвуд» — командное приложение сотрудников тематического парка. Это PWA без сборки: чистый JavaScript, один `index.html`, общая база Supabase.

- Сайт: https://dreamwood.pages.dev (Cloudflare Pages, автодеплой из ветки `main`).
- Репозиторий: https://github.com/GamosSup/DreamWood
- База: Supabase, проект `bvlwpfmtcdgfsomvwqrp`.
- Владелец и главный заказчик: Игорь («Игорян», админ приложения). С ним общаемся по-русски, неформально, коротко и по делу.
- Язык интерфейса и всех текстов: русский. Слово «Дримвуд» никогда не склоняем (пишем «в приложении Дримвуд», «команда Дримвуд»), это правило владельца.

Что в приложении: «Сегодня», график и отметки, ротации по зонам парка, аттракционы, чек-листы смены, заявки, новости и афиша, поломки и инциденты, задачи, «Мой блокнот» (дела, привычки), «Спасибо», геймификация (опыт, уровни, значки, питомцы, тамагочи, мини-игра, автомат с вещами, ежедневные задания).

## 2. Как устроен код
Сборки нет. Файлы подключаются обычными `<script>` в `index.html` в строгом порядке, глобальные переменные общие. Порядок важен:

`config, logo, app, qc, dgx, attract, ext1, ext2, ext3, ext4, myfiles, today, roted, xlsx, rep, plan, grow, pet, game, gacha, gacha2, gacha3, companion, prof, pet25d, gold, brief, fx, push, tour`

| Файл | За что отвечает |
|---|---|
| `config.js` | адрес Supabase и публичный anon-ключ (только публичный!) |
| `app.js` | ядро: вход, роутинг (`go(tab)`), состояние `S`, темы, график, «Сотрудники», роли |
| `today.js` | экран «Сегодня» |
| `ext1.js`…`ext4.js` | чек-листы смены, контакты, заявки, поломки, прочие разделы |
| `myfiles.js` | база знаний → «Моё»: личные файлы, папки и доступ для коллег |
| `roted.js` | ротации (редактор и просмотр) |
| `rep.js`, `xlsx.js` | отчёты и выгрузки |
| `plan.js` | «Мой блокнот»: дела, привычки |
| `grow.js`, `tour.js` | обучение, знакомство |
| `pet.js` | питомцы: виды, цвета, рисование SVG (`petSvg`), экипировка (`PET_GEAR` и др.) |
| `game.js` | достижения, опыт, уровни, профиль, каталог значков `GM_ACH` |
| `gacha.js`, `gacha2.js`, `gacha3.js` | автомат с вещами, списки предметов, ежедневные задания (`dq*` в `gacha.js`) |
| `prof.js` | профиль человека, приветственные окна |
| `pet25d.js` | живые 2.5D-фоны: SVG-слои, питомец и аксессуары, параллакс и студия настроек |
| `gold.js` | отдельный экран «Питомец»: тамагочи, «Золотой лоток», прокачка, энергия, коллекция и награды |
| `companion.js` | Пушок-помощник, обязательное приветствие и журнал настроения |
| `brief.js`, `fx.js`, `push.js` | брифинги, эффекты и подсказки, push-уведомления |
| `styles.css` | все стили; тёмные темы и сезонные темы переопределяются в конце файла |
| `sw.js` | service worker, кэш `dw-vN` |
| `functions/` | Cloudflare Pages Functions: `sb/` — прокси к Supabase, `api/` — файлы, ссылки, push, загрузка |
| `supabase/` | SQL: `schema.sql` и все миграции/правки/подарки по датам |
| `rotations/`, `tools/` | картинки ротаций и скрипт для них |

Стиль кода: плотный, короткие функции, шаблонные строки для HTML, `esc()` для любого пользовательского текста в HTML. Не вводи фреймворки, сборщики и npm-зависимости. Новый код пиши в том же духе и в подходящем файле; крупные независимые куски можно выносить в новый файл (как `gacha3.js`), но его надо добавить в `index.html` и в список кэша `sw.js`.

## 3. Правила релиза (обязательно)
Каждый выкат на `main` поднимает версию, иначе у людей останется старый кэш:
1. В `index.html` заменить `?v=N` на `?v=N+1` у всех файлов.
2. В `sw.js` заменить `dw-vN` и все `?v=N` на новую версию.
3. Новый скрипт добавить и в `index.html`, и в список файлов `sw.js`.
4. Проверить синтаксис: `node --check файл.js`.
5. Коммит и `git push origin main`. Деплой идёт сам.

Текущая версия — `v128`; актуальную всегда сверяй с первой строкой `sw.js`.

## 4. База данных (Supabase)
- Все права держатся на RLS и функциях `security definer` (`is_approved()`, `is_manager()`, `is_admin()`). Клиент ходит под ролью пользователя. Ключ `service_role` в репозиторий и в код не попадает никогда.
- Изменения базы оформляются как SQL-файл в `supabase/` с датой в имени: `migration_ГГГГ-ММ-ДД_тема.sql` (схема и функции), `fix_…` (правка данных), `gift_…` (подарки). Скрипты должны быть безопасны при повторном запуске (`if not exists`, `on conflict do nothing`, проверки в `do $$`).
- Агент **не запускает** SQL на боевой базе сам. Он пишет файл и говорит Игорю, что его нужно запустить. Запуск делается вручную в Supabase → SQL Editor (или его просит сделать Claude, у которого есть доступ к браузеру).
- Если код приложения зависит от новой функции или таблицы, сначала SQL, потом выкат кода (или код должен терпеть отсутствие функции).
- Полезные факты о данных:
  - `profiles`: `role` (`employee`/`manager`/`admin`), `status` (`pending`/`approved`/`rejected`), `team`, `position`, `tab_no`, `day_len`, `cos` (jsonb с оформлением: рамка, имя, фон, значок, титул, питомец `pet`, девиз, о себе…), `lvl_text`.
  - Команды: `R` Рейнджеры, `K` Хранители, `M` Метрополис, `W` «Если дождь» (для ротаций). У руководителей `team = null`: так они попадают в группу «Руководство и остальные».
  - `day_len` может быть только 8, 10 или 12 (рабочих часов в день без обеда).
  - `marks(user_id, day, kind)` — отметки графика (`off`, `otgul`, `do`, `sick`, `vac`). Наличие отметки на сегодня означает «у человека не рабочий день».
  - `roster` — список сотрудников до регистрации, с привязкой `profile_id`; `roster_marks` — их график до привязки.
  - `user_ach(user_id, code, label, bonus)` — выданные достижения. Коды `spec:…` — особые подарки (личные питомцы, титулы).
  - `notifications` (колокольчик): `to_user` — личное уведомление, `for_managers` — руководителям.
  - Билеты автомата: заработано (`gacha_earned`) минус `gacha_state.spent`. Отрицательный `spent` добавляет билеты.
  - Часовой пояс приложения: Москва. Дата «сегодня» на сервере считается как `(now() at time zone 'Europe/Moscow')::date`.

## 5. Игровая часть (самая запутанная, читай внимательно)
- **Питомец**: настройка хранится строкой `sp=вид;bc=цвет;ha=шапка;…` в `profiles.cos.pet`. Виды — `PET_SP` (`[код, название, цвет, нужный_значок]`), цвета `PET_BC`, шапки `PET_HA`, очки `PET_GL`, шея `PET_NK`, грудь `PET_CH`, спина `PET_BK`, в руке `PET_HD`. Рисунки вещей лежат в `PET_GEAR`, `PET_GLX`, `PET_HX`, `PET_BX` (SVG-строки). Шапки рисуются в особой системе координат через `petT(160,104,1.34,180,205,…)`: проверяй картинкой.
- Вещь доступна, если у человека есть нужный значок (`gmHas`). Значки описаны в `GM_ACH` (`game.js`) и регистрируются функцией `sp(...)` в `gacha2.js`/`gacha3.js`.
- Новая особая вещь для человека = (1) рисунок и запись в каталоге в JS, (2) значок `spec:…`, (3) SQL, который выдаёт значок в `user_ach` и пишет `cos` человека.
- **Отдельная вкладка «Питомец» (`v126`)**: на телефоне путь «Ещё» → «Питомец», на десктопе — кнопка в основной навигации. Внутри разделы «Забота», «Лоток», «Образ», «Награды». Старые ссылки на `gold` перенаправляются сюда. С `v127` вкладка не ждёт общий игровой профиль; запрос состояния имеет тайм-аут 12 секунд и кнопку повтора при ошибке. В `v128` `goldView()` завершается сразу, а `goldRefresh()` работает независимо: нельзя возвращать ожидание RPC в `goldView()`, иначе скелетон `go()` через 160 мс удалит `#gold_app` и экран зависнет.
- **Тамагочи и «Золотой лоток»**: клиент в `gold.js`, ресурсы наставника и девяти камней в `stickers/gold/`. В игре используется текущий SVG-питомец с нарядом. Игра длится 30 секунд, энергия — 5 единиц, восстановление по 1 каждые 20 минут. Уровни заботы и старателя дают открытия и билеты. С `v127` каждый день действует одно из трёх событий: тематический камень выпадает чаще, а его первая находка приносит +2 билета.
- **SQL игры**: `supabase/migration_2026-10-30_pet_gold.sql` создаёт `pet_game`, `gold_runs`, RLS и RPC `pet_game_status`, `pet_care_action`, `gold_start`, `gold_finish`. Миграция применена к боевой базе после `migration_2026-10-29_site_visitors_managers.sql`. `supabase/migration_2026-10-30_gold_events.sql` добавляет ежедневные события и их награды; применена к боевой базе.
- **Подарок Тане Хоменко**: `supabase/gift_2026-10-30_tanya_khomenko_50.sql`, +50 билетов; повторный запуск не должен удваивать подарок.
- **Автомат**: предметы `GXI`/`GXI2`/`GXI3` как `[id, редкость, вид, название, значение]`, в базе таблица `gacha_items(code, rarity)`. Новые предметы нужно добавлять и в JS, и в SQL (иначе выпасть не смогут).
- **Ежедневные задания**: `dq_ping`, `dq_status`, `dq_claim` в базе; клиент `dqFill` в `gacha.js`, карточка вставляется на «Сегодня». В выходной (есть отметка) показываются задания выходного дня, фото уходит на проверку админу в хранилище `dqp`.

## 6. Оформление и доступность
- Есть сезонные темы и тёмный режим (`data-theme`, `data-dark`). Любой новый элемент обязан читаться в тёмных темах, в том числе мелкий шрифт. Это больная тема владельца: проверяй контраст.
- В `styles.css` есть правило, которое красит текст в тёмный цвет внутри блоков со светлым inline-фоном. Если внутри такого блока темная карточка, задавай цвет текста явно.
- Телефон — основное устройство. Всё должно работать на узком экране, без горизонтальной прокрутки.

## 7. Как проверять
- Синтаксис: `node --check`.
- Визуально: Playwright. Страница тянет `supabase-js` с CDN, которого в песочнице может не быть, поэтому в тесте подставляют заглушку клиента через `addInitScript` и вызывают нужные функции (`petSvg(...)`, `dqHtml(...)`) прямо на странице.
- Любая правка рисунков (питомцы, вещи) проверяется скриншотом, а не «на глаз по коду».

## 8. Как работать вместе (человек, Claude, Kimi)
- Перед любой работой: `git pull`. Перед пушем: `git pull --rebase`. Не работайте двое в одном файле одновременно.
- Мелкие коммиты с понятным русским сообщением: «vN: что сделано».
- Для крупных задач делай ветку `kimi/тема`, а в `main` вливай только после проверки Игоря.
- Не переписывай и не «улучшай» код, о котором не просили. Не переименовывай глобальные функции: на них ссылаются другие файлы.
- Если нужен доступ, пароль, ключ или запуск SQL, не угадывай и не обходи: напиши Игорю, что именно нужно.
- В итоговом ответе Игорю: 2–3 предложения что сделано, что нужно запустить (SQL) и что проверить. Без пересказа шагов.
- Конфиденциальность: не клади в репозиторий пароли, ключи, номера телефонов и личные данные сотрудников. В тестах и примерах используй выдуманные имена.

## 9. Частые задачи: как делать
- **Дать человеку особого питомца или титул**: см. раздел 5. Образцы: `supabase/migration_2026-11-17_pets_potato_leopard.sql`, `supabase/gift_2026-11-21_nastya.sql`.
- **Добавить сотрудника заранее**: строка в `roster` с `pre_role`, `pre_position`, при одобрении приложение привяжет и применит. Образец: `supabase/migration_2026-10-29_roles.sql`.
- **График «5/2»**: отметки `off` в `marks` на субботы и воскресенья (`extract(dow …) in (0,6)`), `day_len` из допустимых 8/10/12.
- **Новый экран**: функция-вид, регистрация в роутинге `app.js` (`go`, список `MORE_TABS`/`SUBG`), пункт в разделе меню в `ext2.js`.
- **Уведомить людей**: вставка в `notifications` (`to_user` или `for_managers`); push рассылается триггером.
